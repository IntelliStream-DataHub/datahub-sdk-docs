# Agents

An agent is a flow on the flow service whose working step is a model: it reads a window of
events, lets the model act on them with the [MCP tools](./mcp-server), and raises an
**attention** event when the model decides a person should look. The console's Agents form
builds one; this page is the REST surface behind that form, for anyone driving agents from
their own code. There are no SDK methods for it.

| | |
| --- | --- |
| Service | the flow service, `intellistream-flow` (port 8084 locally) |
| Authentication | the same bearer JWT as the API, on every request |
| Needs | the organization's `flow` feature, the `/flows/read` or `/flows/write` organization group, and the usual [data set access](./reference/datasets#access-control) |

## What an agent is {#definition}

A flow whose definition has `"kind": "agent"` and whose steps are fixed:
`read-events` → `agent` → `write-events`. This is the definition the console's form writes:

```json
{
  "schemaVersion": 1,
  "kind": "agent",
  "externalId": "pump_watch",
  "name": "Pump watch",
  "dataSet": "plant_a",
  "processors": [
    { "id": "events", "type": "read-events",
      "properties": { "type": ["error"], "timeField": "createdTime", "excludeSource": ["agent:*"] } },
    { "id": "agent", "type": "agent", "terminate": ["done"],
      "properties": {
        "instructions": "For each event, look up the related resource and raise attention with a summary.",
        "tools": ["event_get", "resource_get", "event_create"] } },
    { "id": "attention", "type": "write-events",
      "properties": { "type": "agent", "subType": "attention", "source": "agent:pump_watch" } }
  ],
  "connections": [
    { "from": "events", "relationship": "success", "to": "agent" },
    { "from": "agent", "relationship": "attention", "to": "attention" }
  ],
  "trigger": { "type": "schedule", "cron": "0 */15 * * * *", "timezone": "Europe/Oslo", "delay": "PT1M" },
  "execution": { "maxAttempts": 2, "timeout": "PT20M" }
}
```

| | |
| --- | --- |
| `kind` | `flow` (the default) or `agent`. |
| An `agent` definition | Must contain an `agent` step with a connection into it. That step may not carry a `retry`. |
| A manual agent | `"trigger": { "type": "manual", "window": "PT1H" }` in place of the schedule. |

## The `agent` processor {#processor}

Listed by `GET /catalog/processors`, category `agent`.

| Property | Default | |
| --- | --- | --- |
| `instructions` | | What the model is to do. Required. |
| `tools` | none | Name patterns of the tools the model may call, `*` and `?` wildcards (`event_*`). Empty means no tools. |
| `effort` | the service's | The model's reasoning effort. |
| `maxIterations` | `6` | Model calls per run. |
| `maxOutputTokens` | | The model's output limit. |
| `turnTimeout` | `PT2M` | ISO-8601 duration for one turn. |
| `maxToolResultChars` | `24000` | Characters of a tool result passed to the model. |

| Relationship | Carries | |
| --- | --- | --- |
| `done` | The items, when the model finishes with `done`. | May be terminated. |
| `attention` | One item per run, holding the attention event row. | Must be connected or terminated. |
| `failure` | The items, when the iteration cap or the model's output limit is hit, or the model server fails. | Fails the run when unconnected. |

Each item leaving the step carries `agent.outcome`, `agent.summary`, `agent.iterations`,
`agent.tokens.input`, `agent.tokens.output` and `agent.toolCalls`.

The model always has a built-in `finish` tool, and calling it is how a run ends. `outcome` is
`done` or `attention`:

```json
{ "outcome": "attention", "summary": "pump_12 raised three errors in a row and its bearing temperature is climbing." }
```

### Which tools the model gets {#tools}

The step reads the servers' `tools/list` and keeps the
[annotations](./mcp-server#annotations) they carry:

| A tool with | Is |
| --- | --- |
| `destructiveHint: true` | Never offered, whatever `tools` says. |
| no `readOnlyHint: true` | Mutating. In a preview it is refused with `preview: not executed`, and an attempt that called one is not retried: the second attempt fails with `not retried: the first attempt changed data`. |
| `readOnlyHint: true` | Called freely. |

Every `event_create` call gets `source: agent:<flow externalId>` added, so the agent's own events
can be told apart, and kept out of its next window with `excludeSource` below. A `429` from a tool
server is waited out once, for its `Retry-After` and at most 10 seconds, then retried.

## `read-events` and `write-events` {#read-write-events}

| Step | Property | |
| --- | --- | --- |
| `read-events` | `timeField` | Which timestamp the window bounds: `eventTime` (the default), or `createdTime`, when DataHub recorded the event, which catches late arrivals. |
| `read-events` | `excludeSource` | Patterns of `source` values to leave out, `*` wildcard, characters `[A-Za-z0-9_.:*-]`. Sent to the API as an [advanced filter](./reference/events#advanced-filters): `["agent:*"]` becomes `(source IS NULL OR source NOT LIKE 'agent:%')`. |
| `write-events` | `source` | The provenance written on every event the step creates. |

## Endpoints {#endpoints}

Three endpoints are new for agents. The rest of the flow API is unchanged: save and validate
(`POST /flows`, `POST /flows/validate`, `PUT /flows/{id}`), deployment
(`PUT /flows/{id}/deployment`), and runs (`POST /flows/{id}/runs`, `POST /previews`,
`GET /runs`, `GET /runs/{id}`, cancel and rerun).

| Endpoint | |
| --- | --- |
| `GET /flows?kind=flow\|agent&cursor=&limit=` | The listing, filtered by kind. Omit `kind` for both. Each `FlowView` carries its `kind`. |
| `GET /agents/tools` | What the tool servers advertise, asked as the caller. |
| `GET /runs/{id}/transcript?attempt=&after=` | A run's transcript, the conversation between the model and the tools. |

### `GET /agents/tools` {#agents-tools}

Needs `/flows/read`. Returns the API server's tools and, when the service is configured with
it, the analysis server's, with hints for a picker:

```json
{
  "tools": [
    { "server": "datahub-api", "name": "event_get", "description": "...", "readOnly": true, "destructive": false }
  ]
}
```

A server that does not answer is a `503`, problem type `tools-unavailable`.

### `GET /runs/{id}/transcript` {#transcript}

| Parameter | Default | |
| --- | --- | --- |
| `attempt` | the latest | Which attempt of the run. Out of range is a `400`. |
| `after` | `-1` | Return rows with a greater `seq`. Poll with the last `seq` you hold. |

```json
{
  "runId": "...",
  "attempt": 1,
  "status": "RUNNING",
  "rows": [
    { "seq": 0, "time": "2026-10-12T01:00:00Z", "kind": "system", "payload": { "text": "..." } }
  ]
}
```

| `kind` | `payload` |
| --- | --- |
| `system` | `{ text }`, the instructions given to the model |
| `user` | `{ text }`, the events |
| `assistant` | `{ text }` |
| `tool_call` | `{ id, name, args, mutating }` |
| `tool_result` | `{ id, name, text, isError, millis }` |
| `usage` | `{ iteration, inputTokens, outputTokens, cacheReadInputTokens, cacheCreationInputTokens, stopReason, millis }` |
| `note` | `{ text }` |
| `truncated` | `{ bytes }`, the transcript was cut at the 1 MB cap |

`404` unless the caller may write the flow: a transcript carries tool results from any data set
the run's identity can reach. Rows are served from the run store while the run is live and from
history afterwards, and kept with the run's history, 90 days by default.

## The attention event {#attention-event}

When the model finishes with `attention`, the `write-events` step writes one event into the
flow's data set:

```json
{
  "externalId": "agent:pump_watch:<runId>",
  "type": "agent",
  "subType": "attention",
  "status": "open",
  "source": "agent:pump_watch",
  "eventTime": "<when the run finished>",
  "metadata": { "summary": "...", "runId": "...", "flow": "pump_watch" }
}
```

The console dismisses one by writing the same `externalId` with status `dismissed`. To list the
ones still open, `POST /events/latest` with:

```json
{ "filter": { "type": ["agent"], "subType": ["attention"] }, "status": ["open"] }
```

## Cost and data {#cost}

The organization's own [model credential](./reference/tenant#llm-settings) pays for every run,
and the events in the window, every tool result and the instructions go to that model provider.
